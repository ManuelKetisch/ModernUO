# Explain technical work clearly

Use one term per concept. State the result, then show the relevant conditions
and steps in the order a reader uses them. Keep file paths, commands, game
terms, and decisions exact. Use active voice and put the actor near the action.

For procedures, name the starting state, each action, the observable result,
and the recovery step if it matters. For implementation notes, include the
source and what was tested. Use [player-facing copy guidance](../plain-language-ui-copy/SKILL.md)
for text inside the game.
