# Write player-facing text

Use the terms players see in nearby gumps and commands. State what the control
does or what happened. Keep labels short. Use direct instructions for recovery
when an action fails. Keep build status, test names, code identifiers, and
working labels in developer documentation.

Follow the owning client's or server's localization conventions. Check that
the text fits the actual gump, including at different scale settings. Check
singular and plural quantities, input labels, and screen-reader names where the
surface supports them.
